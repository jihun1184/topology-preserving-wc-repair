# Version 1.0.0 publication checklist

This is operational guidance, not a claim that the release is published.

1. Verify candidate commit, tag target, file manifest and exact asset digests.
2. Obtain final author approval of publication and MIT code / CC BY 4.0 record
   licenses for inventoried files. Repository-admin access alone is not ownership.
3. Recheck remote main, tags and releases. Do not force-push or update main.
4. Push only the approved new version tag and publish its approved GitHub assets.
5. Download the actual asset, verify SHA/commit/tag and record the final URL.
   Only then use post-publication availability text in the submission workflow.

No Zenodo integration or identifier issuance is part of this workflow. Original
manuscript text, proofs, figures and experimental tables are preserved.
